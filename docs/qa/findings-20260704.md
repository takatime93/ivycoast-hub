**Method:** Read-only static analysis. No code modified.

> Persisted by Noa from the audit run. Line numbers were captured before the localization

## Executive Summary

Structurally sound: no `innerHTML` violations, no localhost auth bypass, no auto-invoice creation,
allowlist runs for all users. Firebase/Apps Script integration is clean; design tokens mostly honored.

Main drag on the premium feel: 19 native `alert()` dialogs where toasts belong, receipt modal can't be
Escape-dismissed, one orphaned unreachable view, and 29+ hardcoded color/font values in JS `style.cssText`
bypassing tokens. Three correctness issues to address: stale `CLAUDE.md` invoice schema, a duplicate
`var totalPct`, and a silent `fetchAllData` failure path.

---

## P0 — Correctness / Security
- **P0-1 CLEAN:** No localhost auth bypass — `onAuthStateChanged` runs `ALLOWED_EMAILS.includes(user.email)` unconditionally; no bypass/devMode patterns anywhere.
- **P0-2 CLEAN:** Zero `innerHTML` across the file.
- **P0-3 CLEAN:** No auto-invoice creation; `handleShopifyWebhook` is neutered; receipt auto-create only on explicit "paid".
- **P0-4 FIX — `CLAUDE.md` invoice schema is stale.** Actual Invoices sheet (`apps-script.js:18`) has three extra trailing columns `paymentBank | paymentNote | marginNote` that `saveInvoice()` writes. CLAUDE.md:97 omits them → anyone following CLAUDE.md to build invoice rows will misalign columns. **Fix:** update CLAUDE.md to match apps-script exactly.
- **P0-5 — `fetchAllData` failure is silent.** `.catch` only logs; on network failure with empty cache, all views show empty with no explanation. **Fix:** surface an offline/stale status in the catch.

## P1 — Broken UX
- **P1-1** Receipt modal has no Escape handler (only invoice/order/score-drawer do). Add `closeReceiptModal()`/`closeReceiptPreview()` to the global Escape block.
- **P1-2** `_openQuickEdit()` overlays (CRM quick-edit, formulator batch-edit) have no Escape handler — keyboard trap. Add a self-removing keydown listener.
- **P1-3** Orphaned `#ivycoast` view — rendered every init (`renderCategoryGrid("IVYCOAST", ...)`) but no nav tab reaches it. Add a tab or remove the view + its render call.
- **P1-4** 19 native `alert()` calls (validation + info). Replace with `showFormulatorToast()` / inline field errors. Lines: 8471, 8978, 8980, 14937, 15395, 15402, 17203, 17385, 18197, 18312, 19315, 19326, 19911, 19913, 21265, 21708, 21768, 23367, 25856.
- **P1-5** `fetchAllData` fires 10+ synchronous renders in one call stack before paint. Gate non-home renders on active tab (lazy render on tab click).

## P2 — Polish / Design System
- **P2-1** Duplicate `var totalPct` inside `buildInvoicePreviewTo` (~21720 & ~21755) — remove the inner one.
- **P2-2** `getInvPricingParties()` called 3× back-to-back in `saveInvoice` (~21695) — reuse existing `_invParties`.
- **P2-3** 29+ hardcoded color/font values in JS `style.cssText` bypass tokens (e.g. 7660, 9448, 9920, 12780–12786, 12903+, 13133+). Biggest design-drift risk — extract to named classes; prioritize CRM cards + assignee badge.
- **P2-4** No `role="dialog"` / `aria-modal="true"` / `aria-labelledby` on the four modal overlays.
- **P2-5** Invoice/Receipt numbers generated client-side from cached array → concurrent-session collision risk. Prefer server-side `generateInvoiceNumber_()` (exists, unused), or add per-user suffix.
- **P2-6** Firebase scripts loaded without SRI (jsPDF has it). Add `integrity` + `crossorigin`.
- **P2-7** Batch response not checked for `data.error` (per-entity callers are) → a quota error could wipe in-memory data. Guard at start of the `.then()`.
- **P2-8** `exportInvoicePdf()` calls `saveInvoice()` which closes the modal mid-async; new invoices PDF a client-generated number pre-confirmation. Save first, download in `.then()`.
- **P2-9** Mobile invoice preview rendered at `scale(0.35)` — illegible. Below 600px, hide split preview, show a "Preview" button → full-screen overlay.

## P3 — Nice-to-Have
- **P3-1** `debounce` discards arguments (fine for current use).
- **P3-2** `DOCS` static array; "27 files / 8 categories" subtitle can drift.
- **P3-3** `ivh-empty` hardcoded `#80868b` vs `ivh-empty-sm` token — standardize.
- **P3-4** No keyboard shortcut for new Invoice/Receipt (Board & CRM have `n`).

## End-to-End Connectivity

**Working:** Order→Invoice (`orderId`/`orderNumber`); Invoice→Receipt (on "paid"); CRM Contact→Invoices/Stock/Receipts (by `contactId`, email fallback for receipts); Product→Soap Batch (`linkedProductId`); Batch→Formulator.

**Gaps (links that should exist):**
- Orders row → CRM contact (has name/email, no "Open in CRM").
- Invoice row → CRM contact (contact name is plain text, not a link).
- Customers drawer → CRM contact (no link even when email matches).
- Orders row → linked invoice indicator (Documents knows, Orders doesn't surface it).

---

## State of the App

**Solid:** auth model; security rules; invoice/receipt create-save flows (optimistic + toasts + recovery);
CRM detail tabs; the Soap Formulator (most complete feature); the token system; batched data fetch w/ cache.

**Fragile:** client-side invoice/receipt number uniqueness; silent `fetchAllData` failures; orphaned
`#ivycoast` view; 29+ inline hardcoded styles; receipt-modal & quick-edit Escape gaps.

**Top 5 for premium feel:**
1. Replace 19 `alert()`s with toasts/inline errors (highest leverage).
2. Add "View in CRM"/"View Contact" links across Orders, Invoices, Customers.
3. Fix Escape on receipt modal + `_openQuickEdit` overlays.
4. Add `role="dialog"` + `aria-modal` to all modals.
5. Fix mobile invoice preview (35% scale → full-screen overlay button).
